- CameraShake 接口

# 1. 战斗系统主干

## 1.1 玩家技能系统

当前玩家已经具备四个基础技能：

- 横 / 轻击
- 竖 / 重击
- 撇 / 远程 projectile
- 捺 / Dash / 突刺

技能数据通过 `SkillData` 配置。

技能释放后会进入现有链路：

```text
输入
→ SkillData
→ PlayerSkillController
→ Hitbox / Projectile / Dash
→ DamageInfo
→ Damageable
→ Health / Shield / Toughness
```

### 已完成内容

- 技能可配置 Damage
- 技能可配置 ShieldDamage
- 技能可配置 ToughnessDamage
- 技能可配置击退 / 击飞 / 受击控制
- Projectile 可生成并移动
- Dash 有位移、无敌、Dash Hitbox
- 技能方向已修正，避免转身后特效使用旧方向

### 注意事项

突刺 / Dash 是否削盾不是程序 bug，取决于 `SkillData.ShieldDamage`。

规则：

```text
ShieldDamage = 0：
不能削盾，只触发 Shield Block Cue

ShieldDamage > 0：
可以削盾，触发 Shield Hit Cue
```

# 2. 护盾系统

## 2.1 当前规则

护盾敌挂有 `ShieldComponent`。

护盾存在时，`Damageable` 采用护盾优先逻辑：

```text
如果 ShieldComponent 存在且 HasShield = true：
    只处理护盾
    不扣血
    不扣韧性
    不击退
    不僵直
    不击飞
    直接 return
```

破盾那一下也只负责破盾，不做溢出伤害。

破盾后下一击才开始扣血和扣韧性。

## 2.2 护盾反馈

当前护盾相关反馈分成三类：

```text
shieldHitCue：
能削盾技能打在盾上，盾值下降

shieldBlockCue：
不能削盾技能打在盾上，盾值不下降

shieldBreakCue：
护盾从 >0 变为 0
```

对应资源在：

```text
Feedback_Enemy_ShieldDummy.asset
```

音效侧可以分别配置：

- `shieldHitCue.randomAudioClips`
- `shieldBlockCue.randomAudioClips`
- `shieldBreakCue.randomAudioClips`

# 3. 韧性 / 破韧系统

## 3.1 当前规则

护盾敌挂有 `ToughnessComponent`。

护盾破掉后，攻击会开始扣韧性。

当前韧性规则：

```text
韧性 > 0：
敌人仍然扣血
但免疫 Knockback / HitStun / Airborne

韧性归零：
进入 Break

Break 期间：
敌人停止 AI
仍然可以继续扣血
不叠加击退 / 僵直 / 击飞

Break 结束后：
韧性恢复满
AI 恢复
血量不恢复
```

# 4. 血条 / 护盾条 / 韧性条 UI

## 4.1 敌人头顶 UI

三类敌人都有敌人血条。

护盾敌额外有：

- 护盾 overlay
- 韧性条

当前结构：

```text
HealthBarRoot
  Background
    HealthFill
    ShieldOverlayFill
  ValueText

ToughnessBarRoot
  Background
    Fill
  ValueText
```

当前设计：

- `HealthFill` 用红色条表示血量
- `ShieldOverlayFill` 覆盖在血条上方表示护盾
- `ToughnessFill` 用独立细条表示韧性
- Fill 使用 `RectTransform.anchorMax.x` 缩短
- Root / Background / Text 不参与缩放

## 4.2 当前尺寸

```text
HealthBarRoot = 126 x 16
ToughnessBarRoot = 126 x 12
```

护盾敌：

```text
HealthBarRoot worldOffset.y = 1.58
ToughnessBarRoot worldOffset.y = 1.25
```

## 4.3 死亡显示

敌人死亡时：

- 血条隐藏
- 护盾 overlay 随血条隐藏
- 韧性条隐藏
- 敌人对象仍按 `EnemyDeathHandler.destroyDelay = 0.8f` 延迟销毁

这个延迟是配置项，目前保留，用于后续死亡动画 / 死亡特效 / 音效收尾。

# 6. 碰撞系统

## 6.1 玩家与敌人身体碰撞

当前规则：

```text
普通移动：
玩家不能穿过敌人

Dash Active：
玩家可以穿过敌人

Dash 结束：
恢复玩家与敌人身体碰撞
```

实现：

- 使用 `PlayerEnemyCollisionController2D`
- 不再使用 `Physics2D.IgnoreLayerCollision`
- 改为逐 Collider 调用 `Physics2D.IgnoreCollision`
- 避免 LayerCollisionMatrix assertion 问题

## 6.2 敌人之间

敌人之间允许重叠，不互相挤压。

当前通过逐 Collider 忽略 Enemy vs Enemy 碰撞处理。

## 6.3 Dash 结束重叠处理

Dash 结束时如果玩家仍在敌人体内：

- 先进行安全点搜索
- 找到安全点后移动玩家并恢复碰撞
- 找不到安全点时等待分离后再恢复碰撞
- 避免立即恢复碰撞导致抖动或弹飞

```text

敌人吃局部时缓
```

```text

Time.fixedDeltaTime
```

```text
EnemyBrain2D.GetEnemyTimeScale()
```

敌方 Projectile 通过：

```text
ProjectileMover2D
```

读取局部倍率。

# 10. 随机音效系统

`FeedbackCue` 已支持：

```text
audioClip
randomAudioClips
```

播放规则：

```text
如果 randomAudioClips 有 2 个及以上有效 Clip：
    随机选择，但避免连续播放同一个

如果 randomAudioClips 只有 1 个有效 Clip：
    可以重复播放

如果 randomAudioClips 为空或全 null：
    fallback 到 audioClip
```

每个 `FeedbackCue` 独立记录：

```text
lastRandomAudioClip
```

不会不同 Cue 之间互相影响。

当前使用 `GetAudioClip()` 的 Binder：

- `EnemyCombatFeedbackBinder`
- `PlayerSkillFeedbackBinder`
- `SwordArtFeedbackBinder`
- `PlayerDamageFeedbackBinder`

# 14. Animator 当前状态

## 14.1 已完成

`Player.controller` 当前为最小状态机。

默认状态：

```text
Idle
```

移动：

```text
Idle -> run1
Condition: IsMoving == true

run1 -> Idle
Condition: IsMoving == false
```

动作入口：

```text
LightAttack / Attack_Horizontal -> Light Attack
HeavyChargeStart -> Chargeattack
HeavyStage1 / Attack_Vertical -> Chargeattack1
HeavyRelease -> Chargeattack2
RangedAttack / Attack_LeftFalling -> Ranged Attack
DashStart / Attack_RightFalling -> Bliink Strile
Hurt -> hit
Death -> die
```

动作返回：

```text
Light Attack -> Idle
Chargeattack -> Idle
Chargeattack1 -> Idle
Chargeattack2 -> Idle
Ranged Attack -> Idle
Bliink Strile -> Idle
hit -> Idle
```

`die` 不返回 Idle。

## 14.2 已知问题

当前 Animator 参数面板仍有旧残留参数，例如：

```text
run1
run2
idleCharg
run1Charg
run2Charg
Hold
Release
Tap
die
Slash
Liangyi
Blilnk
Ranged
hit
```

这些旧参数不应作为 Transition 条件。

后续建议清理这些无用参数，但清理前需要全项目搜索确认没有代码使用。

## 14.3 语义补充

已确认：

```text
run1 = 起步
run2 = 跑步循环 / 跑步中
Turn = 角色转向
```

仍未明确：

```text
Slash
Ling1
Ling2
Liangyi Fall
```

这些状态暂时不要乱接。

## 14.4 后续 Animator 建议

移动可以进一步改成：

```text
Idle -> run1
run1 -> run2
run2 -> Idle
```

其中：

```text
run1 -> run2：起步动画播完后进入跑步循环
run2 -> Idle：停止移动后回待机
```

Turn 暂时不要接，除非代码中新增明确的 `Turn` Trigger。
